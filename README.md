# Mad Mallard Platform

Portable, open-source Docker Compose deployment for a shared business application platform.

## Planned applications
- Matomo — web analytics
- Umami — privacy-focused website analytics
- Supabase — backend platform
- Metabase — business intelligence
- Chatwoot — customer support
- n8n — workflow automation
- Horilla — HR management
- Authentik — identity and access management
- Homepage — application portal

## Design requirements
- One primary `compose.yaml` and an `.env.example`.
- Reuse database engines, Redis and infrastructure only where upstream software supports it; isolate databases, accounts and data.
- Preserve vendor-supported Supabase services and dependencies.
- Support deployment to any compatible Docker Compose host without fixed host IPs.
- Integrate with an existing Traefik, monitoring and backup stack without duplicating those services.
- Provide optional standalone deployment prerequisites and clear configuration.
- Support shared branding and SSO where upstream applications allow it; document limitations.
- Use supported, pinned container versions; never commit secrets.
- Include validation, tests, security checks, backup/restore instructions and operational runbooks.

## Umami analytics

Umami runs on the existing PostgreSQL service, using a separate `umami` database and login. Configure `UMAMI_DB_PASSWORD` and `UMAMI_APP_SECRET` in your local `.env` (use a URL-safe database password). The UI is available at `http://localhost:3005` by default; change `UMAMI_PORT` if necessary.

**One-time database provisioning:** the PostgreSQL volume is already initialized on existing installations, so scripts in `init/postgres` will not run again. Create the isolated role and database before starting Umami. In a PostgreSQL superuser session, run `CREATE ROLE umami LOGIN PASSWORD '<your-UMAMI_DB_PASSWORD>';` and `CREATE DATABASE umami OWNER umami;` (substitute your secret locally, never commit it). If the role/database already exists, reuse it instead of recreating it.

Start with `docker compose up -d umami`, check `docker compose ps umami`, and visit `http://localhost:3005`. Change Umami's default admin password immediately. To collect website metrics, add the per-website tracking script generated by Umami to each site's pages; creating a website or map alone does not collect traffic. The script must be reachable from visitors' browsers over HTTPS in a production deployment—`localhost` works only for local testing. For a separately maintained Umami fork, this stack uses the published Umami image rather than building the fork.
